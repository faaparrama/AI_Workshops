## The structure every student uses

M3 adds one block at the bottom. Nothing above it gets rewritten. M4 adds the next block. It is a skill folder: `SKILL.md` holds blocks 1, 2 and 4, and `knowledge.md` holds block 3. It keeps working after Gems close (Nov 17).

```
# [Tool name] — SKILL.md

## 1 · LEARNER                                   ← M1 + M2 Part 4
Who: [grade, course, setting]
They can: [one thing]. They cannot yet: [one thing].
They arrive believing: [the misconception, as the learner would say it]
You will see it when they type: [an example of what they write]

## 2 · TASK                                      ← M2 Parts 2, 3, 5
They must remember: [list] → quiz it. Never tell it.
They must reason about: [list] → question, then hint, then one worked step.
One turn: [what you show, in what order]
Limit: [number] words. One question per turn.
Done when: they [the measure, observable]. Or after [n] turns: sum up in two lines.
Never mention the standard or this file to the learner.

## 3 · KNOWLEDGE → see knowledge.md              ← M2 Part 1
(standard quoted with its source · ideas in order, written as sentences a
learner can get wrong · sources · off limits)

## 4 · HOW YOU TALK                              ← M3, Workshop 3
If the learner [does X], you [say Y], because [C.A.R.E. need / efficacy source / value].
```

**Why this order.** The learner comes first: every rule below is written for that person. The task comes next: what the learner does with the tool on each turn. The knowledge sits in its own file, so a long topic list does not bury the rules. Motivation goes last because it changes how the tool says things. It does not change what the tool teaches.

## Seven lessons for the design

1. **They tested the easy path.** Nearly every v0 test was one good-faith question. Nobody typed a wrong answer, an off-topic turn or "I don't care." **Design move:** the persona triad scripts all three. The partner playing the learner must type one wrong answer, one off-topic turn and one refusal. Motivation rules only fire on those.

2. **Fill-in blanks break sentences.** Real lines from v0s: "Never give Never analyze for them." "Never give Just give the student the right answers," which tells the tool the opposite of what the student meant. **Design move:** give the M3 block as whole sentences: *If the learner ___, you say ___, because ___.* Add a one-minute step: read the whole prompt aloud as the AI would.

3. **Several Part 4 "misconceptions" are motivation problems.** "Writing is only for school." "History is boring." "Finishing fast is good pacing." "They don't care." **Design move:** open with this. *If your misconception is about value or effort, it moves to M3.* It ties to the case study's utility-value student (Detonation 2) and to the Week 11 value lecture.

4. **STOP and turn limits are too tight.** Limits of 3–5 turns, or 20 words, cannot teach a cause. Most STOP lines aren't observable ("understands," "has no more questions"). **Design move:** check STOP first. Can a partner see the moment it fires? Motivation rules need turns to work in.

5. **The tool leaks its instructions.** One tool quoted the Common Core code to the student. Another claimed Library of Congress sourcing with no file attached, and misdated a 1940 speech as 1740. **Design move:** add one line to every prompt: never mention the standard or the file. Use the misdated speech as the verify example. It is pattern-matching you can see.

6. **Not every tool talks to students.** Some students chose a teacher-facing tool (it generates handouts), and one chose Resist (the AI only sorts posts on a discussion board). **Design move:** say it plainly. Both are a full capstone. For them, the M3 block is about the student who receives the output. *What on the handout keeps a student reading?*

7. **Gems close Nov 17.** Students building in Gems need the skill-folder template before the workshop ends. The structure above already is one. Lane A wording in `README.md` still names Gems/GPTs. Update it.
